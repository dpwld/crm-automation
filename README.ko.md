# CRM Automation

[English](README.md) · 한국어

CRM Automation은 고객사, 연락처, 영업 기회, 엔지니어링 요구사항, 견적과 고객 후속 업무를 관리하는 비공개 CRM입니다.

![CRM Automation — 가상 고객사와 영업 파이프라인](docs/images/overview.png)

*README의 예시 화면에는 실제 로컬 API로 저장한 가상의 회사, 연락처, 영업 기회를 사용합니다. 이 예시 데이터는 호스팅된 워크스페이스에 자동으로 삽입되지 않습니다.*

<a id="before-you-start"></a>

## 시작하기 전에

데이터베이스는 비어 있는 상태로 시작합니다. 처음 로그인하면 CRM을 열기 전에 회사에서 사용하는 사양서 스키마를 설정하세요. 조직 정보, 담당자 목록과 고객 데이터는 직접 입력해야 합니다. 회사 계정, 인증 정보, 연락처나 실제 운영 데이터는 포함되어 있지 않습니다. 선택적으로 사용할 수 있는 스크린샷 예시 데이터 도구는 로컬에서만 동작합니다.

| 요구사항 | 필요한 기능 | 설정 방법 |
| --- | --- | --- |
| Node.js 22.13 이상과 npm | 로컬 개발 및 빌드 | Node를 설치한 다음 `npm ci` 실행 |
| Cloudflare D1 바인딩 `DB` | 모든 데이터 저장 및 CRM 설정 | 마이그레이션은 `drizzle/`에 있으며, 바인딩은 `.openai/hosting.json`에 선언되어 있음 |
| 운영 환경 인증 | 비공개 호스팅 워크스페이스 | 기존 Sites 인증 또는 [자체 호스팅 안내](docs/SELF-HOSTING.md)에 따른 본인의 Cloudflare Access 애플리케이션 사용. 로컬 개발에는 두 계정 모두 필요하지 않음 |
| R2 바인딩 `BUCKET` | 업로드한 문서, 제작 파일, 검사 사진, 고객 첨부파일과 체결된 NDA | `.openai/hosting.json`에 선언되어 있으며, 로컬에서는 Wrangler가 저장소를 에뮬레이션함 |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | AI 정보 입력, 문서·사양서·발주서 추출, 초안 수정, 이메일 요약·분류와 NDA 필드 초안 | 선택 사항인 서버 전용 비밀값. 해당 기능을 사용하려면 두 값 모두 필요 |
| `GMAIL_ACCESS_TOKEN`, `GMAIL_SENDER_EMAIL` | 사용자가 명시적으로 실행하는 이메일 발송, NDA 요청과 고객 요구사항 요청 | `gmail.send` 권한이 있는 본인 소유 Google 계정으로 설정. 토큰이 만료되면 교체해야 함 |
| `PUBLIC_APP_URL` | NDA 및 고객 요구사항 링크 | 선택 사항. 이 워크스페이스의 HTTPS 오리진을 서버에 설정 |
| 조직의 법적 명칭·주소, 법인 설명, 직접 준비한 NDA 계약 조항, 서명 권한자 | 출력 문서의 조직 정보 및 서명 업무 | **CRM settings**에 본인의 값 입력 |

**호스팅된 버전은 소유자 전용 비공개 상태입니다. 소유자가 호스팅 공개 범위를 의도적으로 변경하기 전에는 외부 고객이 링크를 이용할 수 없습니다. 서명 및 고객 요구사항 엔드포인트는 로컬에서 테스트할 수 있으며, 이 저장소는 비공개 접근 범위를 변경하지 않습니다.**

핵심 고객사·연락처·영업 기회 관리, 수동 요구사항·사양서 작성, 고객사 문서·업무 실행, 활동·댓글·반응, 변경 요청 및 후속 업무에는 OpenAI나 Gmail이 필요하지 않습니다. 외부 인증 정보가 없으면 설정 오류를 표시하며, 가짜 추출 결과나 이메일 발송 성공 상태를 만들지 않습니다.

### 회사 사양서 스키마 설정

최초 설정에서는 회사가 실제로 사용하는 사양서 형식을 입력합니다. 스키마 이름과 한 개 또는 두 개의 값 열 이름을 지정하고, 섹션과 필드를 추가한 뒤 각 필드의 형식을 텍스트 또는 숫자로 선택하세요. 저장하면 다음 단계로 진행할 수 있습니다. 나중에 **CRM settings → Company specification schema**에서 형식을 수정할 수 있습니다. 설정은 브라우저 저장소가 아닌 소유자별 D1 레코드에 저장됩니다. 새 고객사 및 영업 기회 사양서는 저장된 형식을 사용하고, 기존 버전과 고객 요청은 생성 당시의 필드 스냅샷을 유지합니다. 사용자가 입력한 필드 이름과 값은 원래 언어로 유지됩니다.

### 직접 준비해야 하는 데이터

| 입력 경로 | 직접 제공하는 데이터 | 형식 및 필수 필드 |
| --- | --- | --- |
| 고객사 양식 | 실제 고객 조직 | 이름. 참조 번호는 자동 생성되며 업종·단계·우선순위는 기존 CRM의 열거값을 사용. 연락처, 주소와 금액은 선택 사항 |
| 연락처 양식 | 고객 담당자 | 이름과 연결할 고객사. 고객 요청 발송에는 유효한 이메일 주소 필요 |
| 영업 기회 워크스페이스 | 고객 영업 기회 | 제목과 고객사 또는 사내 업무 구분. 영업 기회 번호는 자동 생성되며 담당자는 직접 구성한 목록에서 선택 |
| 사양서 설정 | 회사의 요구사항 형식 | 스키마 이름, 사용자 정의 값 열 1~2개, 필드 1~80개. 각 필드에는 섹션, 고유한 이름, 선택적인 단위·기호, 텍스트 또는 숫자 형식, 단일 값 또는 열별 개별 값 구성이 필요. 미리 입력된 업종별 필드는 없음 |
| 요구사항 편집기 | 고객사 또는 영업 기회 요구사항 | 저장한 스키마를 사용하며 각 버전은 필드 정의와 열 이름을 유지 |
| 고객 요구사항 워크북 | 실제 고객 응답 | 해당 비공개 요청에서 워크북을 다운로드. `Spec Sheet` 시트, 고객 식별 정보, `Section`, `Field`, `Symbol`, `Unit` 열 제목, 직접 설정한 값 열과 필드 행을 유지하고 값을 입력. 수식은 거부되며 용량 제한은 2 MB |
| 사양서 추출 | 실제 고객 사양 문서 | 기존 SheetJS 파서로 텍스트로 변환하는 XLSX 또는 PDF·이미지. 추출에는 AI 인증 정보 필요 |
| 문서 정보 추출 | 실제 견적서·발주서·청구서 | PDF 또는 이미지. AI 인증 정보가 필요하며 추출한 필드는 검토 가능한 초안으로 유지 |
| 첨부파일 | 소유권이 있는 실제 파일 | 제작·문서 파일은 최대 50 MB. 고객 요구사항 첨부파일은 최대 2 MB이며 파일 형식과 확장자 검사 적용 |

이 서비스에는 범용 CSV 고객 가져오기, 자동 메일 수집, 은행 연결 또는 서비스 간 재무 API가 없습니다. 청구서 이관은 이 워크스페이스에 소유자에게 속한 재무 이관 레코드를 생성하며, 별도 재무 서비스에 전달되었다고 표시하지 않습니다.

## 빠른 시작

```sh
git clone https://github.com/dpwld/crm-automation.git
cd crm-automation
npm ci
npm run setup
npm run dev -- --port 4323
```

로컬 설정에는 ChatGPT 계정이나 유료 API 키가 필요하지 않습니다. `npm run setup`은 서비스를 빌드하고 저장소에 포함된 로컬 마이그레이션을 적용하며, 데이터를 자동으로 채우지 않습니다. [설치 안내](docs/INSTALLATION.md), [본인 Cloudflare 계정에서 자체 호스팅](docs/SELF-HOSTING.md), [기여 안내](CONTRIBUTING.md)를 참고하세요.

저장소에 포함된 마이그레이션을 바로 적용할 수 있습니다. `db:generate`는 `db/schema.ts`를 수정한 뒤에 필요합니다. 로컬 개발 서버는 스타터의 루프백 전용 로그인과 `.wrangler/state` 아래의 Miniflare D1/R2 영구 저장소를 사용합니다. `npm start`는 게이트웨이 및 통합 검증을 위해 빌드된 Worker를 실행합니다. Sites 배포 파이프라인은 선언된 바인딩을 생성하고 마이그레이션을 적용합니다.

선택적인 외부 연동은 서버 환경 변수를 사용합니다. 네이티브 개발 서버에서는 `.env.example`을 `.env.local`로 복사하고 본인의 값을 입력한 뒤 `npm run dev`를 다시 실행하세요. 빌드된 Wrangler Worker에서는 템플릿을 버전 관리에서 제외된 `.dev.vars`로 복사하고 `npm start`를 다시 실행하세요. 호스팅 인증 정보는 비공개 배포의 서버 비밀값 설정에 저장해야 합니다. 인증 정보 이름에 `NEXT_PUBLIC_` 접두사를 붙이거나 `.dev.vars`·`.env` 파일을 커밋하면 안 됩니다.

기존 호스팅 인스턴스는 Sites 로그인을 사용하고, 독립 배포는 문서에 설명된 Cloudflare Access 모드를 사용합니다. `npm run dev`는 스타터의 루프백 전용 로그인 화면을 활성화합니다. 미들웨어는 외부에서 들어오는 사용자 식별 헤더를 제거하고 로그인 후에만 로컬 세션을 제공합니다. 격리된 빌드 Worker API 검증에서는 테스트 도구가 루프백 Worker에 일회용 사용자 식별 헤더를 보냅니다. 독립 실행 중인 개발 Worker를 인터넷에 공개하지 마세요.

## 업무 흐름

인터페이스는 기존 CRM 컴포넌트와 도메인 함수를 옮겨온 것으로, 고객사 및 영업 기회 탭은 기존 구조를 유지합니다. 헤더에서 간결한 CRM 설정 대화상자를 열 수 있습니다. 이 저장소에는 인접한 플랫폼 워크스페이스가 포함되어 있지 않습니다.

- 고객사 보드 또는 표에서 시작해 검색·필터를 사용하고, 고객을 즐겨찾기에 추가하거나 연락처·상세정보 패널을 엽니다.
- 타기팅 조사, 최초 연락, 영업 활동, 다음 조치와 후속 업무를 기록합니다. 고객사 및 영업 기회별 타임라인, 댓글, 멘션과 반응을 함께 관리합니다.
- 독립적인 영업 기회를 만들고 최초 연락, NDA, 사양, 견적, 고객 발주서, 청구서, 완료 단계로 진행합니다. 실행 상태는 제조·시험·배송·사후관리의 의미를 유지합니다.
- 요구사항 표를 편집하고, 부품 사양의 버전을 관리하며, 최종 버전을 지정해 엔지니어링에 전달합니다. 고객사별 제작 체크리스트, 부품, 조달 상태, 입고, 검사와 실험을 추적합니다. 별도의 조달·부품 추적 서비스는 연결되어 있지 않으며, 해당 서비스로 보내는 작업은 비활성 상태로 표시됩니다.
- 견적서, 발주서와 청구서의 초안을 작성하고 카탈로그 품목, 명세 항목, 통화, 할인, 세금과 연결된 개정본을 관리합니다. 영구 저장되는 카운터로 거래처·연도별 문서 번호를 부여합니다. 인쇄 및 PDF는 저장한 조직 정보와 약관을 사용합니다.
- 이메일과 서비스 오리진을 설정한 뒤 비공개 고객 요구사항 요청을 발송합니다. 고객은 구조화된 값과 첨부파일을 저장하거나 제출할 수 있습니다. 검토 화면에서는 현재 부품과 비교하고 제출된 내용을 새 초안 버전에 적용합니다.
- CRM 설정에 직접 준비한 NDA 계약 조항을 저장한 뒤 서명을 요청합니다. 문서 스냅샷과 해시를 보존하고, 고객의 직접 그린 서명 또는 입력한 서명과 동의를 받은 다음 권한자가 명시적으로 추가 서명합니다. 체결된 PDF와 서명 인증서는 R2에 저장되며 이메일 발송 실패는 화면에 남습니다.
- 설정을 마친 뒤 실제 AI 연동으로 정보 입력, 추출, 비교, 초안 작성과 이메일 분류를 수행합니다. AI 결과는 사람이 검토할 초안으로 유지됩니다.

[기능 대응 목록](docs/FEATURE-PARITY.md)은 원본 기능 영역과 구현의 대응 관계를 보여줍니다. [구현 보고서](docs/IMPLEMENTATION-REPORT.md)에는 검증 결과와 아직 필요한 외부 설정이 정리되어 있습니다.

### 선택 사항: 가상 데이터로 README 화면 미리 보기

`npm run dev -- --port 4323 --host 127.0.0.1`로 서버를 시작한 뒤 실행하세요.

```sh
npm run readme:seed
# 실제 로컬 CRM 화면을 캡처한 뒤, 이 예시 데이터만 제거합니다.
npm run readme:cleanup
```

이 도구는 HTTP 루프백의 4323번 포트만 허용하고, 네이티브 로컬 로그인을 확인한 뒤 미리 정해진 `readme-crm--` ID의 레코드를 삽입합니다. 같은 예시 네임스페이스가 이미 있으면 실행을 거부하며, 기존 레코드를 갱신하는 upsert는 하지 않습니다. 예시 데이터에 예시 이외의 레코드가 연결되어 있으면 정리 작업도 거부합니다. 시작, 마이그레이션 또는 배포 시 자동 실행되지 않으며 이메일·AI 제공자를 호출하지 않습니다. 스크린샷 예시는 실제 고객 데이터와 분리해 사용하세요.

## 구조

React/Vinext가 Cloudflare Workers에서 실행됩니다. D1은 소유자·엔터티·ID로 구성한 키 아래에 검증된 기존 도메인 JSON 레코드를 저장하며, 별도의 원자적 문서 번호 카운터, 비공개 링크 해시, 작업 보호 정보, 파일 메타데이터와 연동 실행 로그도 보관합니다. 브라우저에서 데이터를 변경하는 모든 요청은 인증된 서버 엔드포인트를 거치고, 테이블·작업·필드 허용 목록 및 소유자 검사를 적용받습니다. R2 객체는 비공개이며 소유권 또는 유효한 비공개 링크를 확인한 후에만 스트리밍됩니다.

기존 Supabase 데이터 함수의 호출 규약은 `lib/data`에 유지됩니다. 클라이언트는 이제 소유권이 적용되는 D1 엔드포인트로 쿼리를 전송합니다. Supabase 계정이나 회사 백엔드는 필요하지 않습니다. 업무 데이터는 브라우저 localStorage에 저장하지 않으며 패널 크기, 고정 상태, 정렬 기본 설정은 로컬에 저장될 수 있습니다.

SheetJS 0.20.2는 검토된 기존 벤더 아카이브에서 유지한 버전입니다. 패키지 라이선스와 함께 제공된 제3자 라이선스 고지는 의존성과 함께 남아 있습니다. Pretendard 글꼴 라이선스는 `public/fonts/OFL.txt`에 있습니다. 저장소는 공개 열람할 수 있으며, 저장소 전체에 적용되는 오픈소스 라이선스는 부여하지 않았습니다. 제3자 구성요소에는 각각의 라이선스가 적용됩니다.

<a id="verification"></a>

## 검증

```sh
npm test
npm run typecheck
npm run build
```

루프백 주소 `CRM_TEST_URL`에서 격리된 빌드 Worker를 실행한 상태로 `npm run test:server`를 실행하면 실제 D1/R2를 대상으로 HTTP 검증을 수행합니다. 기본 주소는 `http://127.0.0.1:4313`입니다. 이 테스트는 일회용 테스트 소유자의 예시 데이터를 기록하므로 별도의 영구 저장 디렉터리를 사용하세요. 도메인·서버 검증 명령과 관측 결과는 [IMPLEMENTATION-REPORT.md](docs/IMPLEMENTATION-REPORT.md)에 기록되어 있습니다. 자동 검증에서는 외부 발송과 유료 AI 호출을 제외합니다.

<a id="current-limitations"></a>

## 현재 제한사항

- Google OAuth 승인·갱신과 정기 메일 수집은 구현되어 있지 않습니다. 본인 소유 계정의 `gmail.send` 액세스 토큰을 수동으로 설정해야 하며, 만료되면 실패가 표시됩니다. AI 이메일 요약은 저장된 이메일 본문을 사용하고 부분적인 요약임을 표시합니다. 메일함에서 첨부파일을 가져오는 기능은 구현되어 있지 않습니다.
- 호스팅은 소유자 전용 비공개 상태를 유지합니다. 고객 서명·요구사항 링크를 외부에 배포하기 전에 공개 범위를 명시적으로 결정해야 합니다.
- 별도의 Engineering, Procurement, Approvals, DocsHub, Studio 및 전역 NDA 애플리케이션은 이 CRM 저장소의 범위 밖입니다. 고객사 NDA 흐름과 수신자 서명 페이지는 기존 CRM에 직접 필요한 기능이므로 유지합니다.
- 재무 이관은 원래 청구서 페이로드를 로컬에 저장합니다. 별도 재무 서비스로 인증된 전달을 하려면 서비스 간 연동 규약을 설정해야 합니다.
- 담당자 목록은 한 계정의 데이터 안에서 담당 배정과 멘션을 지원합니다. 여러 사용자가 공유하는 테넌트 및 실시간 접속 상태는 구현되어 있지 않습니다.
- 계약서 PDF는 기존의 영어·라틴 문자 제한을 유지합니다. 서버는 지원되는 법적 명칭 등의 정보를 검증하며 문서를 조용히 손상시키지 않습니다.
- 정기 작업이나 백그라운드 작업이 자동으로 활성화되지 않습니다. 연동 시도는 저장되지만 자동 스케줄러는 명시적인 설정이 필요합니다.
